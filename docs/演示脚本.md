# 开卷 · 8 分钟演示脚本

## 演示前 10 分钟检查

- [ ] `node server.mjs` 已启动（终端保持可见，万一要重启）
- [ ] 浏览器两个标签页：`/console` 和 `/h5`，标签顺序：console 在前
- [ ] 中控台点过「重置演示」，活动回到「策划中」
- [ ] 页面缩放 100%；/console 窗口 ≥1280×720，无横向滚动
- [ ] 关闭微信及其他通知窗口
- [ ] 备用：手机热点已开（本方案不需要网络，但评委可能要求接真模型）

## 评委可能问的问题

**Q：AI 会不会替人写感悟、冒充读者？**
不会。活动札记必须由领读人署名，AI 只产草稿；读者端的 AI 结果有独立浅绿标识，没有头像、不进讨论串（设计指南 §5.7）。

**Q：断网了怎么办？**
现在就是离线跑的——每个 Agent 失败自动回放模板，流程不中断。`.env` 配一行就能接真模型。

**Q：为什么不是 Next.js？**
原计划是。现场网络 20–50 KB/s，Next 和 Prisma 装不上，改成 Node 原生实现保证演示稳定。页面结构和设计 token 按指南做，赛后可平移。

**Q：社区会不会变成鬼城？**
活动是内容生产线，频道是容器。每场活动机械产出问题云、札记、金句，新频道第一天就有内容（设计思路 §2 判断一）。

**Q：商业模式？**
政府购买打底（≤50%）+ 出版社新书营销 + 品牌茶歇赞助；C 端活动免费，用问题门槛筛选而不是收费。

## 失败兜底

| 情况 | 处理 |
|---|---|
| 服务挂了 | 终端 `node server.mjs` 重启，10 秒恢复，数据在 data.db 里不丢 |
| 浏览器卡住 | F5 刷新，SSE 会重新同步状态 |
| 想重跑一遍 | 中控台「重置演示」→ 重新点开始 |
| 时间只剩 3 分钟 | 跳过 0:30–1:10 和 6:00–6:40，直接「跑流水线 → Gate1 → Gate2 → 读者端看札记」 |
